# Lighter–Arcus 资金档配置

先把钱包本金与合约名义额度分开，再以实际启动入口所读取的配置为准。一次资金调整只修改用户确认的公开配置，不碰凭据。

## 明确额度和范围

确认每所钱包资金、每所累计名义上限、每币每所名义上限、允许币种和层数。钱包有 5000U 不意味着名义上限必定为 5000U，也不等于允许 5000U 保证金或最大亏损。区分固定币数量与美元金额、单腿与双腿、账户权益与可用余额。

用户只要求 YAML 检查时，列出所有相关公开配置并解析，不扩展到源码审计、账户查询或 SSH。若已有可靠入口/生效字段证据，复用并注明来源；缺少证据时只能报告静态值，不能声称运行时保护已接线。需要源码确认时另行说明必要范围。

## 查实际入口和覆盖

在有授权的范围内查启动脚本、命令参数和配置关系，明确主策略、行情和执行配置，以及临时模式覆盖。项目曾以 `scripts/start_lighter_arcus.sh` 读取 `arbitrage_segmented.yaml`、`monitor_lighter_arcus.yaml`、`arbitrage_lighter_arcus.yaml`，但新任务要核实实际入口。默认 monitor 与显式 live 必须分开描述。

解析所有相关公开 YAML，拒绝重复键及格式错误；列出每份文件的角色、生效与历史状态。不要因历史文件有一个保护字段，就把它当当前策略的保护。`enabled: false`、旧入口或未接线的字段不得计入有效保障。

## 协调数量与门槛

- 每币确认 base quantity、split order size、盘口最低数量、数量精度/步长、最低名义和 max segments；全局默认与币级覆盖同时核对。
- 计算 `split × price` 是否达到两所最低名义；计算 `base × layers × price` 是否受币额度限制。固定数量不会自动按币额度缩小，价格变化可能使第二层或第一层被拒绝。
- 明确 split 与 base 的关系；深度应服务于实际单笔检查量，不能把大 base 和旧小深度混用。若实现可能按剩余数量拆单，不把 split 误称为每笔恒定量。
- 每所累计上限须覆盖全部币种；若有效动态上限为 `min(固定上限, 账户 total × multiplier)`，按该公式说明，不能只引用固定值。
- 费用用比例、价差用百分数时写清单位。沿用用户确认费用和滑点，不擅自查账户费率、降风险或改策略来保证成交。
- 区分净开仓门槛、毛价差、天然价差扣除、开平费用及滑点保护；报价满足门槛不代表实际盈利。余额禁开/风险退出、止损、持仓期限等仅对已确认生效路径作结论。

具体 5000U 档仅作为算例：需要时读取 [references/5000-example.md](references/5000-example.md)，不要把它复制成其他账户的默认值。

## 精准修改和验收

修改前保存将改文件的逐字节副本与 SHA-256，并列出允许变化的 YAML 路径。保留其他字段和注释风格，避免整文件重排。修改后比较全部相关公开文件：只允许指定文件、指定数值和相关解释注释变化。

至少验证 YAML 唯一键/格式、前后路径和值、未改文件字节一致、币级覆盖、层数/量/精度/深度/最低名义/额度协调、费用单位、模式与禁开门槛。需要时用离线边界价格和账户 total 算例；不得把计算检查说成真实执行路径测试。

交付修改文件、精准 diff、哈希、有效配置摘要、通过/跳过项和回滚范围。回滚只恢复本轮文件，恢复前核对是否有后续编辑。将静态 YAML 验收、离线代码验收、远端部署和实盘运行分别报告。

本技能默认停在本地配置；部署、启动、停止、重启、下单只有用户明确授权相应动作时才可执行。授权部署也不等于授权启停交易。永不读取或输出 `.env`、带认证的交易所配置、私钥、日志及交易数据来完成普通参数调整；这些文件不进入公开快照或 Git 提交。
